## Project
Course Confusion Radar Application

## Purpose
This document explains how the Iteration 2 velocity proxy was used to adjust
the Iteration 3 backlog.

## Iteration 2 Velocity Proxy

The Iteration 2 velocity is calculated in
[Iteration 2 Review](iteration-2-review.md) and applied here rather than
restated.

Iteration 2 completed effort:

| User Story | Effort |
|---|---:|
| US5 | 1 day |
| US6 | 3 days |
| US7 | 1 day |
| US8 | 1 day |
| US10 | 1 day |
| **Total** | **7 days** |

The Iteration 2 velocity proxy is therefore **7 effort-days per iteration**,
matching the Iteration 1 velocity proxy exactly, and it is used here as the
planning baseline for Iteration 3 capacity.

## Backlog Adjustment Decision

Iteration 3's original backlog (2 effort-days) is well below the 7 effort-day
velocity baseline. There are no further backlog user stories to pull forward:
US1-US8 and US10 are already done, and US9 is the last user story in the
[Milestone 1 Plan](milestone-1-plan.md). The backlog is therefore left
unchanged at US9 only.

This is expected for Iteration 3. Practical 8 also requires TDD and Mock
Object work (see [Test Plan](test-plan.md) and the Mock Object tests added
this iteration) alongside the feature work, which uses the remaining
capacity that a sixth user story would otherwise have filled.
